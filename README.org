* Nostril: Nostr Interface layer

A [[https://github.com/nostr-protocol/nostr][nostr]] client written in [[https://github.com/jtimon/til][Til]] language.

*Warning: Nostril is an early development prototype, not ready for use.*
Configuration, storage formats and APIs may break without compatibility or
migration guarantees. Use disposable test identities, not valuable keys or data.

- =nostril-cli= is the local command-line client in =mode nostril_client=.
- =nostril-relay= is the local relay harness in =mode nostril_relay=.
- =nostril-gui= is the graphical client in =mode gui=.
- =nostril= is the reusable client library in =mode lib=.

** Getting started

Nostril requires an installed Til with =std/crypto= and its secp256k1 archive
and interpreter twin. See the generated [[file:doc/til-dependency.org][Til build dependency]].
From the repository root:

#+begin_src sh
./make.til
./bin/nostril-gui
#+end_src

Without configuration the GUI creates an ephemeral keypair from OS entropy and
stays local-only. Type into the composer and press Enter or =Send= to create a
signed NIP-01 kind-1 event. For a stable identity and a following feed, see
[[file:doc/accounts.org][accounts and configuration]].

To attach GUI sessions to the local live relay, start it, then run
two GUI instances from separate terminals in this repository:

#+begin_src sh
./bin/nostril-relay --live
./bin/nostril-gui --relay
#+end_src

Both commands accept an optional IPC endpoint after the flag. The GUI shows
each outgoing note as pending, accepted, or rejected (with the relay's reason).
Pending notes retry automatically after disconnection or a lost reply, retaining
the original signed event. Both relay and GUI deduplicate by verified event ID.
Accepted means the relay accepted the event in memory, not that every subscriber
received it. The feed requests the latest 50 matching notes, then stays live.
Configured accounts and follow lists persist; notes, pending publications and
relay deduplication are session-only. The local relay retains its latest 256
verified events for replay while it is running.
Separate identities must follow each other to see each other's notes.

The GUI opens a kind-1 subscription (=REQ= with =limit:50=), collects bounded
history until =EOSE=, and resubscribes after reconnecting. Notes are ordered by
timestamp with deterministic ID tie-breaking; use the mouse wheel to browse
older notes. The relay routes events only to matching subscriptions; =CLOSE=
removes that client's subscription. See
[[file:doc/transports.org][the local protocol]] for supported filters and transport details.

To connect to one public relay instead, pass its WebSocket URL:

#+begin_src sh
./bin/nostril-gui --relay wss://relay.damus.io
#+end_src

The WebSocket transport is implemented in a compiled Til library, including its
callbacks. It verifies TLS certificates and hostnames, subscribes to live kind-1
events from self and followed authors, and preserves pending signed publications
across reconnects. See [[file:doc/websocket.org][WebSocket transport and dependencies]].

To run the scripted local NIP-01 exchange, start the relay and then run the CLI
from another terminal:

#+begin_src sh
./bin/nostril-relay
./bin/nostril-cli
#+end_src

The CLI sends =REQ= with =limit:0=, receives =EOSE=, and sends =CLOSE= over
NNG IPC. This is a development harness, not yet a general relay. Build only
the library with =./make.til library=, run the smoke and local transport tests
with =./make.til test=, or remove generated output with =./make.til clean=.

See [[file:doc/build.org][building Nostril]], [[file:doc/architecture.org][the initial architecture]], and
[[file:doc/transports.org][the transport design]]. The [[file:doc/websocket.org][WebSocket dependency decision]] records
the selected libwebsockets profile and the alternatives considered.

** Transport direction

Nostril will first exercise its transport-independent protocol model through
local NNG communication and project-owned custom Til modes. NNG can remain an
IPC backend while WebSocket, WebRTC, or other backends are added for remote
relays and transport-specific NIPs. Backend selection must not fork the event,
filter, subscription, or relay model.

** Accounts and configuration

Nostril interprets =$XDG_CONFIG_HOME/nostril/init.til= (default
=~/.config/nostril/init.til=) in-process with TilVm, following Tiled's host-prelude
and shared startup-library patterns. Accounts live in =accounts/= beside init.
=--create-account= saves a plaintext owner-only
key and prints its public key; the init file names/selects accounts and relays.
=--follow= and =--unfollow= persist the selected account's signed follow list.
The GUI's =Account:= picker switches between registered accounts; =Following=
adds/removes follows for the active account and updates its feed immediately.
Use =Name= beside a follow to assign a per-account NIP-02 petname. Your names
are the primary feed labels; public keys remain visible and can be copied.
The =Copy npub= button copies your public identity. Follow input accepts hex,
=npub=, =nprofile= and their =nostr:= URI forms, with NIP-19 checksum validation.
Switching starts a fresh feed session and clears the draft and pending retries.
See [[file:doc/accounts.org][setup, ownership and storage details]]. Encrypted key storage is tracked in
[[file:issues/open/2.org][issue #2]]. The [[file:issues/process.org][issue workflow]] is adapted from Tiled.

Nostril is an experimental Til project, not an urgent replacement for mature
Nostr software. Users who need a complete Nostr client today should use one of
the existing clients available in other languages.

Til's =std/crypto= is also experimental and has not had a security review. In
particular, Til does not yet guarantee secure erasure of managed secret-key
copies. The GUI account is suitable for this prototype, not for valuable keys.

** Dependencies

- [[https://github.com/jtimon/til][Til]]
- CMake 3.24 or newer and a C compiler
- OpenSSL development headers/libraries and system CA certificates
- [[https://github.com/nanomsg/nng][NNG]] 1.11, vendored under =vendor/nng/= and built into =gen/nng/=
- [[https://github.com/warmcat/libwebsockets][libwebsockets]], pinned under =vendor/libwebsockets/=; see [[file:doc/websocket.org][the selection record]]
