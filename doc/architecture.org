* Initial architecture

[[file:../README.org][Nostril]] | [[file:build.org][Building and running]] | [[file:transports.org][Transport design]]

Nostril begins with one reusable library and three thin hosts. The split keeps
Nostr protocol and relay behavior independent of command-line or graphical
presentation.

- =lib/nostril/nostril.til= is the canonical =mode lib= entry point.
- =modes.til= defines the project-owned =nostril_client= and =nostril_relay=
  modes and their automatically imported NNG support.
- =src/nostril_cli.til= is the local client host.
- =src/nostril_relay.til= is the local relay harness.
- =src/nostril_gui.til= is the =mode gui= host with an ephemeral account and
  in-memory signed-event timeline.
- =tests.til= is the canonical =mode test= suite for the public library,
  local NNG transports, and client/relay process boundary.

The build creates Til's generated binding, then selects a narrow public binding
that links the repository-local static archive and Til's secp256k1 support.
All hosts use that same interface; they should not develop separate protocol
implementations.

** Intended boundaries

The library owns NIP-01 kind-1 serialization and signing, event ID and signature
validation, and parsing of relay =EVENT= envelopes. It should eventually also
own other event kinds and additional relay messages and
transport-independent client behavior. Hosts own argument handling, display
state, input, and user interaction.

The GUI keeps signed event JSON in a host-owned =Vec(Str)=. The shared account
library owns either the configured persistent key or an ephemeral fallback when
no account is configured. It signs each submission as a kind-1 event. With
=--relay= the GUI sends signed notes through the local live
feed. Its timeline holds relay envelopes and accepts incoming messages only
after shared validation; matching event IDs are suppressed. Nonblocking receives
are capped at 32 messages per frame to keep input/rendering responsive.

=lib/modes/nostril_live.til= owns the local transport helpers and the timeline
acceptance operation shared by GUI and integration tests. The host owns and
closes its sockets. Signing, validation, verified IDs, and OK parsing remain in
libnostril; NNG types do not cross the public library ABI.

The GUI owns an in-memory outbox of signed JSON, verified ID, publication state,
and an outstanding-request flag. It queues each ID once and submits one pending
entry at a time through NNG REQ. Only a matching complete OK reply changes its
state; receiving the event on the feed is not an acknowledgement. NNG retains
the request bytes and retries after a lost reply or reconnect. Rejected entries
retain the reason and are not retried. Closing the GUI discards the outbox.

The live relay owns a REP socket, a routed pair1-poly socket, a set of accepted
IDs, a timestamp-ordered 256-event replay cache, per-connection subscriptions,
and pending replies. It verifies before deduplication, routes new valid events
to matching subscriptions,
and replies to every valid retry with accepted/duplicate. A restart clears
the relay's set and cache; client timeline deduplication still prevents repeated display.
The small =src/relay_signal.c= adapter sets a signal-safe stop flag for SIGINT
and SIGTERM; the Til main loop then closes sockets and releases its state.

The library parses bounded REQ/CLOSE controls and evaluates filters; the
host-side live module owns the connection/subscription state. Native NNG pipe
handles identify connections, not public keys. The GUI owns a feed-readiness
state machine, waits for EOSE before starting queued publications, and renews
its author-filtered kind-1 subscription with a 50-note historical query after
reconnecting. Pre-EOSE notes are bounded and sorted before timeline insertion;
EOSE opens live delivery without applying the historical limit to new events.
Timelines/outboxes remain in memory; only accounts and follow lists are
currently persisted.

For ws/wss URLs the GUI instead uses =lib/websocket/nostril_ws.til= through its
compiled library binding. Callback bodies, receive assembly, publication state
and retries are Til code. =lib/websocket/abi.c= handles only libwebsockets struct
setup and native symbol registration/lifetime. The exported callback is a real
C function address, not a Til closure value. Both execution modes consume the
same compiled callback implementation. See [[file:websocket.org][the WebSocket transport]] for ownership,
limits, TLS verification, and the independent loopback tests.

User configuration follows Tiled's TilVm/shared-library pattern. The GUI and
interpreted XDG init (default =~/.config/nostril/init.til=) share
=libnostril_startup.so= through the host API prelude; init stages
account declarations, selection and relay preference, then the host validates
and adopts the selected account. Secret keys remain in the compiled account
owner. Signed follow files are locked and atomically replaced. Both transports
receive the same self-plus-follows request and recheck that filter locally.
See [[file:accounts.org][accounts and configuration]] for the API and storage contracts.

NNG is the initial local transport and integration harness. It may remain a
production IPC backend after remote transports are added. WebSocket, WebRTC,
and other backends should carry the same protocol messages and use the same
state machines rather than duplicate NIP behavior. See
[[file:transports.org][the transport design]] for local testing, custom Til modes,
backend capabilities, and specification-derived issue planning.

Transport-specific resources should have explicit ownership and teardown.
Encrypted key storage is tracked in [[file:../issues/open/2.org][#2]]. Current owner-only plaintext storage
and signing inherit Til =std/crypto='s experimental status and do not promise
secure erasure of managed secret-key copies.
