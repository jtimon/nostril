* WebSocket dependency selection

[[file:../README.org][Nostril]] | [[file:build.org][Build requirements]] | [[file:transports.org][Transport design]]

** Selected: libwebsockets

Nostril uses [[https://github.com/warmcat/libwebsockets][libwebsockets]] for the public-relay transport.
It is C, permissively licensed, and supplies the HTTP opening handshake,
WebSocket framing, nonblocking client lifecycle, TLS integration, and write
backpressure. This keeps those mechanisms out of Nostril's protocol library.
The upstream source tree is broad; our compiled profile is deliberately narrow.

The source under =vendor/libwebsockets/= is the =v5.0-stable=
snapshot at commit =a842936f881921b6462b3328cce8e700b7a7ecd2= (version 5.0.0).
It has one local DNS-cache lifetime fix, described below.
The branch name is provenance, not a floating dependency. Build configuration
is maintained separately in =lib/websocket/CMakeLists.txt=.

- Source archive: https://codeload.github.com/warmcat/libwebsockets/tar.gz/a842936f881921b6462b3328cce8e700b7a7ecd2
- Archive SHA-256: =aec47546b8b298fb10b021896873637d9bd1efcb9e0f6f165ac045f24e275cc2=
- License: upstream =LICENSE=; primarily MIT, with the documented permissive
  component licenses preserved. Upstream examples and test fixtures are retained
  for provenance but are not enabled by the application build.
- Updates must select an exact upstream revision, replace the snapshot, review
  changed options and licenses, and rerun the dependency and application tests.

** Build and TLS choice

The native profile builds PIC static and shared libraries with HTTP/1.1,
WebSocket client support, OpenSSL TLS, and the built-in poll event loop. It
enables asynchronous DNS and its UDP/system-state dependencies so hostname
resolution does not block the GUI thread. It
disables the server, examples, HTTP/2, HTTP/3/QUIC, MQTT, Secure Streams,
compression extensions, image/HTML helpers, and external event-loop plugins.
Generic crypto helpers remain enabled because this snapshot's TLS certificate
fingerprint and HMAC code uses them even without Secure Streams.
The small LEJP parser also remains enabled because the upstream system-policy
object references it; Nostril continues to use its own NIP JSON parsing.

OpenSSL is a system dependency, not another vendored tree. Install its development
package (Ubuntu/Debian: =libssl-dev=) and system CA certificates. Normal OpenSSL
discovery is performed by CMake. An alternate development prefix can be supplied
through CMake's standard =CMAKE_PREFIX_PATH= environment variable. Builds do not
download or install dependencies automatically.

=./make.til= and =./make.til test= build into =gen/websocket/= and =gen/lib/=.
The =library= target continues to build only libnostril. Native static/shared smoke executables
verify the configured protocol features, upstream revision, and repeated client
TLS context creation/destruction. The Til suite runs both executables in its
interpreted and compiled passes; these tests do not contact the network.

The full suite additionally runs an independent loopback WS/WSS fixture using
Python's =websockets= package (tested with 10.4, using its legacy server API).
It generates a one-day test certificate/key under =tmp/= with the OpenSSL CLI
and removes them after success. It tests fragmented messages (including EVENT
before EOSE), ping/pong, malformed JSON, binary/oversized/invalid-UTF-8 rejection,
CLOSED/NOTICE, dropped acknowledgements, reconnect/resubscription, unchanged
signed retries, and CA/hostname rejection. It does not publish to public relays.

** Til transport and native boundary

=lib/websocket/nostril_ws.til= is a compiled Til library. Its callback body,
message assembly, receive queue, publication queue/state, subscription handling,
event verification/deduplication and reconnect policy are all Til.
=lib/websocket/abi.c= only handles native context/connect-info layout, URI storage,
callback-symbol registration, the nonblocking service entry, and destruction.
There is no native callback queue or C Nostr implementation.

The library owns heap-stable sessions behind integer handles. =nostril_ws_open=
returns zero on setup failure; every successful handle must be passed to
=nostril_ws_close= exactly once. All operations stay on the opening thread.
Callbacks execute synchronously during connect, poll and teardown. The library
keeps userdata alive until context destruction has finished, then removes the
session and releases its owned buffers. Returned strings belong to the caller;
input strings are borrowed for the call. Vendor structs do not cross the host API.

The generated =gen/websocket_api.til= loads =gen/lib/libnostril_ws.so= on both
Til execution modes. The shared libwebsockets dependency is staged beside it,
using the generated library's origin-relative runtime lookup. Its native ABI
glue is compiled against the pinned headers and asserts the callback constants
and USize64 layout used by this Linux build.

The GUI selects this transport for =--relay ws://...= or =--relay wss://...=;
IPC endpoints keep the NNG backend. WebSockets send standard Nostr REQ/CLOSE and
=["EVENT",event]= messages without NNG headers or terminating NULs. A fixed
=local= subscription requests live kind-1 events with =limit:0=. The GUI sets
its authors to the active account plus follows through =nostril_ws_subscribe=;
the receiver checks this filter locally too. Matching EOSE
enables queued publications; valid events can arrive before EOSE. CLOSED stops
that subscription, NOTICE is retained for display, and only a complete matching
OK changes publication status. Invalid messages never enter the event queue.

Messages are limited to 64 KiB and the receive queue to 256 events. Libwebsockets
validates text UTF-8; Til rejects binary messages and enforces the assembled size
across fragments. A queue overflow closes the connection instead of growing it
without bound. Publication history and event-ID deduplication remain session
memory, as with the local client.

Disconnected clients retry after one second. Pending publications retry after
one second while subscribed, retaining their original JSON and signature.
Only the writable callback sends frames, with the required LWS_PRE headroom.
Shutdown attempts NIP CLOSE if writable, then destroys the context without
waiting for a peer; disconnect also releases relay subscriptions.

Public =wss://= connections use certificate-chain and hostname verification and
the system CA store. The library's optional CA-file argument exists for explicit
trust configuration and local tests; the GUI uses system trust and exposes no
verification bypass. The poll loop is nonblocking, including DNS resolution.

*** Native callback probe

The callback check made with the installed compiler recorded in
[[file:til-dependency.org][the build dependency record]] found that ordinary Til function values cannot
be passed directly to C as native callbacks, even without captures.

The minimal C boundary was:

#+begin_src c
typedef int32_t (*native_callback)(int32_t, void *);
int32_t nostril_native_callback_probe(native_callback callback, void *state) {
    return callback(7, state);
}
#+end_src

The Til declaration used =Callback := func(I32, Dynamic) returns I32= and
=nostril_native_callback_probe := ext_proc(callback: Callback, state: Dynamic)
returns shallow I32 {}=. A noncapturing Til function attempted to add the
argument to an I32 borrowed through =state= and return the updated count.

- Marking the callback parameter =shallow= was rejected: "shallow parameter
  'callback' must be a scalar or struct type".
- With the ordinary parameter, compilation succeeded, but generated C defined
  =Callback= as =TilClosure *= and passed =&on_event__til_closure= to C.
- Executing the native call failed with SIGSEGV in both compiled and interpreted
  execution. The scratch probe ran in isolated subprocesses with core dumps
  disabled; it is not part of the passing application suite.

That probe tested a closure value, not a compiled library export. A subsequent
probe built a Til library and registered the exported C function address with
libwebsockets. Protocol init/destroy callbacks updated caller-owned Til state
successfully from both interpreted and compiled hosts. This is the path used
by the transport: register =til_nostril_x5fws__ws_callback=, never the address
of a =TilClosure= object. No new Til callback feature is needed for this path.

** Local upstream patch

=vendor/libwebsockets/lib/system/async-dns/async-dns.c= fixes an observed cache
leak when a cached name lacks the requested record type. Upstream removed that
entry from the cache list and left its expiry timer to free it. Context teardown
cancels timers and visits only the cache list, so the detached allocation leaked
if the context was destroyed first. LeakSanitizer reported 131 bytes during the
WebSocket retry fixture. The patch frees unreferenced entries immediately and
keeps referenced entries linked for normal teardown, while bypassing them for
the current lookup. The same ASan transport test passes with leak detection
enabled after the change. Reassess this patch when updating the vendor snapshot.

** Alternatives considered

These comparisons concern architecture and integration effort, not benchmarked
binary size or throughput. A small frame parser is not a complete TLS client.

*** Wslay

[[https://github.com/tatsuhiro-t/wslay][Wslay]] is a small MIT-licensed C99 WebSocket engine; its library CMake build
lists four C sources. It provides framing, callbacks, UTF-8 checks, fragmentation,
and automatic ping replies, while leaving I/O to the caller. It does not perform
the HTTP opening handshake, DNS, connection establishment, or TLS.

It would suit a deliberately transport-independent low-level design, but would
leave more networking code for Nostril to own. The default-branch tip observed
during evaluation was =0e7d106ff89ad6638090fd811a9b2e4c5dda8d40=, dated
2022-08-25. Its unit tests, sanitizer CI and linked Autobahn reports are useful
evidence, but its quiet upstream is a maintenance consideration.

*** libcurl

[[https://curl.se/libcurl/c/libcurl-ws.html][libcurl's WebSocket API]] supports =ws://= and =wss://= with HTTP upgrade, TLS,
proxy support, and =curl_ws_send=/=curl_ws_recv=. It is C under the permissive
curl license. Its multi interface can drive connection setup without blocking
the GUI; the adapter still needs to assemble bounded messages from frame chunks.

It is a strong alternative if HTTP downloads, relay metadata, and proxy support
become central. Its broad source surface is less attractive for a dependency
chosen solely for WebSockets, but it could replace other future HTTP tooling.

*** bq_websocket

[[https://github.com/bqqbarbhg/bq_websocket][bq_websocket]] offers a single-source-file C core, optional platform adapter,
and MIT/public-domain license choice. Explicit message ownership and external
I/O are attractive. The observed default-branch tip was
=6c188d3f0edca38d7a8926e0d30f4c145414ba4c=, dated 2021-01-09.
The reference POSIX/Windows adapter performs DNS and connect before making the
socket nonblocking, so it should not be called unchanged from the GUI thread.
It was not selected given the additional integration and maintenance review.

*** CivetWeb

[[https://github.com/civetweb/civetweb][CivetWeb]] is a permissively licensed C embedded web server with WS/WSS client
APIs. It is worth considering if embedding an HTTP server becomes important;
its server-oriented scope is broader than this client transport needs.

*** Reuse NNG's stream WebSocket support

NNG protocol sockets use its SP WebSocket mapping, which is not ordinary Nostr
WebSocket traffic. Its lower-level =nng_stream= API does support text frames via
=NNG_OPT_WS_SEND_TEXT= and =NNG_OPT_WS_RECV_TEXT=. It is therefore a real option,
not categorically incompatible with Nostr.

However, its stream API's message-boundary and partial-send semantics need
careful evaluation, and the vendored documentation explicitly assigns text
UTF-8 validation to the application. Our NNG build also disables TLS, so WSS
would still require a TLS backend. A dedicated WebSocket client API was selected
instead of adapting the byte-stream interface or depending on private NNG APIs.
