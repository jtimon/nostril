** FIXED #10 Create persistent named accounts from the GUI

Resolution: Account -> New account opens a local-name input; Create/Enter saves
a fresh keypair, registers it and switches through the existing feed reset path.
Back cancels. Duplicate/invalid names report an error without replacing the
current identity or session. The picker includes init and GUI registrations.

GUI names persist in accounts/catalog.tsv under the accounts/.lock. The shared
owner validates a versioned, bounded catalog, rereads it while locked, creates
keys exclusively and atomically writes/syncs the new catalog. Init is never
rewritten. Exact init/catalog pairs coalesce; conflicting name/key pairs fail.
Explicit init selection wins; with no init declarations/selection the first
catalog account is the startup default. Key directories alone are not discovered.
Creation/switch APIs, metadata ownership, 256-entry bound, retained-key behavior
on catalog failure and post-rename sync semantics are documented in [[file:../../doc/accounts.org][accounts]].
