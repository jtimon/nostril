** FIXED #8 Add per-account petnames and petname-first identity labels

Resolution: Following rows have Name/Key controls. The petname editor supports
Save/Enter, Clear name, paste and Back without saving. Assigned names are the
primary following/feed author labels; shortened keys remain visible and full
keys can be copied. Existing notes immediately reflect edits. Names live in the
active account's signed NIP-02 p tags, never in remote profile-name state.

The shared native owner locks/reloads the latest list for uniqueness checks and
atomic signing/storage, then updates its own key-to-name cache. Names are
case-sensitive ASCII letters/digits/underscore, up to 64 bytes; empty clears an
existing follow's name. Duplicate names for different keys, conflicting names
for one key and invalid imported names fall back to key-based labels rather than
being arbitrarily resolved. Rename repairs all tags for a key while retaining
relay hints, extra fields, unrelated tags and content. Publishing the list later
would publish its petnames too; no private alias store or path resolver was added.
Ownership and the new prototype APIs are documented in [[file:../../doc/accounts.org][accounts]].
