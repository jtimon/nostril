*** Reassessment findings

- Installed =std/tilvm= retains the same =mode lib=, host-prelude, checked lookup
  and shared-library lifetime contract. Nostril's implicit API and XDG patterns
  still match Tiled's configuration loader.
- Til's completed embedding work adds native by-value enum payload/niche
  marshalling and canonical generated dependency-binding imports. Native closure
  values are still not C callbacks. Nostril's compiled exported callback remains
  the appropriate libwebsockets boundary.
- Generated dependency composition applies when a library consumes another
  generated API. Nostril's account/WebSocket libraries currently import protocol
  implementation source, so their raw bindings still export overlapping crypto
  and protocol definitions. A switch to generated APIs needs explicit dependency
  boundaries and narrower exports, plus resolution of the startup variadic
  declaration above; replacing the curated files wholesale is not justified.
- Installed =Mode= now has =targets= and =build_hint=, and =link= accepts target
  restrictions. These can make Nostril's build capabilities explicit when doing
  packaging/cross-target work. They do not cross-build its C dependencies, port
  the POSIX account store, or replace the project-owned NNG extension.
- The experimental MLIR backend is a limited numerical/value backend. It is not
  a replacement for Nostril's current C backend and runtime/native dependencies.
- Tiled commit =94d6724= migrated Unicode to Til core/std. Its recorded compiler
  comes from a divergent Til line (Unicode commit =85cce10bd= is not an ancestor
  of the installed revision; their common ancestor is =d2e52f609=). The actual
  installed SDK lacks =std/unicode= and =Str.from_codepoint/read_utf8/is_valid_utf8=.
  Do not copy Tiled's new Unicode calls into Nostril until that SDK support is
  installed. Tiled's relocatable-runtime packaging pattern remains relevant.
- The compiler checkout still tracks temporary string-view lifetimes (#447),
  discarded owned results on return edges (#446), and nested propagating
  reference calls (#443). A source audit found no chained temporary
  trim/substr/strip_prefix calls in Nostril's application, library or tests.
  This is not a claim that those general compiler defects are resolved.

*** Follow-up direction

Keep the shared-library/prelude ownership model. For infrastructure work, pursue
Tiled-style runtime packaging and a deliberately composed generated API surface;
track the concrete variadic-generator failure upstream before removing curated
bindings. Unicode/grapheme reuse depends on reconciling the installed SDK with
Tiled's Unicode line. The application roadmap (for example NIP-02 relay follow
sync) is otherwise unaffected by this compiler update.

Compare the installed compiler/SDK with the previous successful build, inspect
relevant embedding, generated-binding and mode changes, and compare Tiled's
current patterns. Build the library and clients, run the canonical suite and GUI
check, and record compatibility findings and actionable follow-ups.
